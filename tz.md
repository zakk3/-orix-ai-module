2.	Аннотация

Кейс «Разработка ИИ-функционала для формирования выводов в сервисе Орикс» — практическая задача по разработке MVP модуля аналитических выводов, интегрируемого в существующий продукт Орикс.
Актуальность и практическая значимость связаны с необходимостью автоматизации рутинного анализа данных для пользователей сервиса Орикс. Разработанный ИИ-функционал позволит пользователям быстрее интерпретировать сложные показатели, сравнивать свои результаты с бенчмарками и получать готовые текстовые заключения, экономя время специалистов. Итог кейса может быть использован как проект в портфолио.

3.	Кейс направлен на формирование следующих ключевых компетенций:

Профессиональные компетенции (hard skills):
	Data Science & ML: Анализ временных рядов, выявление трендов и аномалий, сравнение распределений, формулирование выводов на естественном языке (NLG).
	Программная инженерия: Интеграция ML-модуля в существующий сервис, разработка API.
	Работа с данными: обработка структурированных данных, сравнительный анализ показателей, расчет метрик.
	DevOps (основы): Работа с Git (Сфера.Код), обеспечение воспроизводимости экспериментов, деплой модели.
	UI/UX (основы): Проектирование интерфейса отображения сгенерированных выводов.

Универсальные компетенции (soft skills):

	Командная работа: Распределение ролей (Data Scientist, Backend Developer, Аналитик), совместная разработка.
	Управление проектом: Планирование спринтов, ведение бэклога в Сфера.Задачи, регулярные демо.
	Продуктовое мышление: Выделение MVP, приоритизация функций (что делаем в первую очередь), обеспечение «гарантированного качества» выводов.
	Коммуникация и презентация: Демонстрации прогресса и финальная защита.
	Системное мышление: Понимание цикла разработки: от бизнес-требований (точность, понятность) до деплоя и документирования модели.

4.	Постановка задания

Название кейса: Разработка ИИ-функционала для формирования выводов в сервисе Орикс (MVP).
Цель выполнения кейса: Закрепить практические навыки командной разработки модуля с использованием ИИ в итеративном формате: планирование, реализация, обеспечение «гарантированного качества» выводов, демонстрации и работа с обратной связью.

Конкретный образ результата: Готовый MVP программного модуля, интегрированного в сервис Орикс (или демонстрируемого как отдельное приложение), который на основе входных данных автоматически формирует текстовые выводы по следующим пунктам:
1.  Вывод о доле потерь в бизнес-индикаторе: Анализ места Моего банка в цепочке банков. Анализ стабильности выводов за 2-3 последних периода.
2.  Вывод о динамике объема прямых потерь: Сравнение с показателем «Средний» по трендам (рост/падение) и темпу роста.
3.  Вывод о динамике объема чистых потерь: Сравнение с показателем «Средний» и с трендами в прямых потерях.
4.  Вывод об уровне возмещения: Сравнение со средним значением и анализ причин отличий на основе диаграммы в разрезе типов рисковых событий/направлений деятельности.
5.  Вывод об отличии в областях концентрации: Анализ распределений по классификаторам (источник риска, тип события, направление деятельности) и стабильности отличий в динамике.
6.  Вывод о нарушении контрольных значений КПУР: Информация о нарушенных порогах, доле банков с аналогичными нарушениями и длительности нарушения.

Требование к качеству выводов:
Формирование выводов должно осуществляться на условиях «гарантированного качества»:
	Процент недостоверных выводов не должен превышать 5%.
	Достоверность включает: отсутствие ошибок в расчетах, логических и смысловых искажений, полноту и понятность формулировок.

Подход к генерации выводов:
1.	Использование техники few-shot learning с предварительной обработкой входных данных
2.	Снижение размерности через векторные представления (embedding) эталонных примеров
3.	Многоуровневая архитектура генерации:
	Шаг 1: Детерминированные вычисления метрик по входным рядам
	Шаг 2: Генерация текста на основе вычислений и промптов
	Шаг 3: Автоматическая валидация сгенерированных выводов алгоритмом-оценщиком

Структура промптов для каждой метрики:
	Доменный промпт: объяснение значений ключей и метрик
	Пользовательский промпт: инструкция по генерации
	Позитивные примеры: эталонные выводы (golden set)
	Негативные примеры: ошибочные выводы для обучения

Требования к данным:
	Наличие размеченного golden set (минимум 5-10 эталонных примеров на каждую метрику для MVP). Будут предоставлены
	Поддержка итеративного дообучения на основе обратной связи
	Возможность расширения golden set в процессе разработки

Функциональные требования:
	Поддержка загрузки входных данных в форматах: JSON/XML через API и/или веб-интерфейс
	Валидация входных данных
	Генерация выводов по 6 типам входных данных (пп.1-6 раздела 3)
	Валидация выводов
	Поддержка выгрузки итоговых данных в форматах: JSON/XML через API и/или веб-интерфейс
	Пользовательский интерфейс с функционалом загрузки входных данных, генерации выводов, возможностью дать реакцию на качество выводов.


Форма и формат отчетности (финальная):
1.	Ссылка на работающий прототип модуля (веб-интерфейс или API endpoint)
2.	Ссылка на Git-репозиторий (Сфера.Код) с историей коммитов
3.	Промпты и конфигурация модели
4.	Техническая документация, включающая:
	Описание архитектуры решения
	Описание используемой ML-модели (алгоритм, гиперпараметры, метрики качества)
	API спецификацию (если применимо)
	Инструкцию по запуску и развертыванию
	Инструкция по обновлению и дообучению
	Отчет о тестировании качества выводов
5.	Финальная презентация (10-15 слайдов) с демонстрацией результатов


Сроки выполнения:

5.	Методические рекомендации обучающимся

Состав команды (4–6 человек):
Рекомендуется распределить следующие роли (возможно совмещение):
•	Team Lead: Управление бэклогом в Сфера.Задачи, коммуникация с куратором проекта со стороны Орикс, координация работы команды.
•	Data Scientist / ML Engineer / Prompt Engineer / LLM Specialist (1-3 чел.): Анализ данных, разработка алгоритмов генерации текста, обучение и валидация моделей, проверка гипотез, обеспечение качества выводов, разработка и оптимизация промптов, настройка параметров генерации, анализ галлюцинаций модели, создание и поддержка golden set.
•	Backend Developer/DevOps: Разработка API, интеграция модели в сервис, работа с базой данных, настройка CI/CD, работа с Git.
•	QA / Analyst: Проверка логики выводов, тестирование на «гарантированное качество», валидация данных, документирование требований.

План работы по спринтам (7 спринтов по 2 недели):
1.	Анализ входных данных Орикс, анализ предоставленных примеров Орикс, проектирование архитектуры ИИ-модуля, настройка инфраструктуры.
2.	Защита спроектированной архитектуры с описанием ее возможностей и ограничений, согласование контрактов, по которым будут передаваться входные / выходные данные из Орикс в модель и обратно, Прототип алгоритма для п.1 (доля потерь).
3.	Реализация выводов пп. 1-2 (Доля потерь, Динамика прямых потерь), демонстрация промежуточных результатов, первые тесты качества выводов.
4.	Реализация выводов пп. 3-4 (Чистые потери, Уровень возмещения), начало верстки интерфейса отчета, демонстрация промежуточных результатов, улучшение NLG, шаблонов генерации, валидация точности выводов.
5.	Реализация выводов пп. 5-6 (Концентрация, КПУР), демонстрация промежуточных результатов, разработка минимально необходимого интерфейса.
6.	Интеграция всех модулей, разработка минимально необходимого интерфейса, генерация PDF.
7.	Повышение качества (снижение ошибок <5%), написание документации, подготовка к защите, финальная защита.
