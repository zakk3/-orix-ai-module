# Pipeline проекта

Данный документ описывает техническую работу pipeline в AI-модуле ОРИКС.

Pipeline — это центральная часть проекта, которая соединяет валидацию, расчёты, генерацию текста и проверку результата.

## Основная роль pipeline

Pipeline выполняет следующие задачи:

1. Получает входной запрос.
2. Создаёт уникальный `request_id`.
3. Проверяет входные данные.
4. Определяет нужную метрику.
5. Запускает соответствующий калькулятор.
6. Получает объект `MetricCalculations`.
7. Передаёт расчёты в генератор текста.
8. Проверяет итоговый результат.
9. Возвращает финальный ответ.

## Общий процесс

```text
request
↓
validate input
↓
select metric calculator
↓
calculate metric
↓
generate analytical text
↓
validate output
↓
return response
```

## 1. Получение запроса

Pipeline получает запрос с данными пользователя.

В запросе обычно есть:

* `metric_type`;
* `period`;
* `series`;
* дополнительные параметры.

## 2. Создание request_id

Для каждого запроса создаётся уникальный идентификатор.

Он нужен для отслеживания обработки запроса и удобной отладки.

## 3. Валидация входных данных

Перед расчётами данные проходят проверку.

Если данные неполные или неправильные, pipeline должен остановить обработку и вернуть ошибку.

## 4. Выбор калькулятора

Pipeline смотрит на `metric_type` и выбирает нужный калькулятор.

Например:

```text
net_losses_bi → Metric1Calculator
loss_buckets → Metric3Calculator
recovery_level → Metric4Calculator
concentration → Metric5Calculator
```

## 5. Расчёт метрики

После выбора калькулятора запускается метод `calculate`.

Калькулятор выполняет все математические операции и возвращает результат в формате `MetricCalculations`.

## 6. Объект MetricCalculations

`MetricCalculations` — это единая модель результата для всех метрик.

Она содержит:

* `metric_type`;
* `period`;
* `my_bank_value`;
* `cluster_avg_value`;
* `difference_percent`;
* `is_below_average`;
* `deviation_threshold`;
* `extra`.

Поле `extra` хранит дополнительные данные, которые нужны для аналитического вывода.

## 7. Генерация текста

После расчётов pipeline передаёт результат в генератор текста.

Генератор использует подготовленные значения и формирует промпт для LLM.

LLM получает уже готовые числа и сценарии, поэтому она не выполняет расчёты самостоятельно.

## 8. Проверка результата

После генерации текст проверяется.

Проверка нужна, чтобы убедиться, что:

* числа не изменились;
* сценарий соответствует расчётам;
* вывод не содержит лишних неподтверждённых фактов;
* стиль соответствует аналитическому отчёту.

## 9. Финальный ответ

После всех этапов pipeline возвращает финальный результат пользователю или в интерфейс.

Финальный ответ содержит:

* рассчитанные показатели;
* сценарий;
* аналитический текст;
* дополнительные данные для проверки.

## Итог

Pipeline объединяет все части проекта в одну цепочку.
Он обеспечивает стабильную обработку данных: от входного JSON до финального аналитического вывода.
