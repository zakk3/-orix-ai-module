# Архитектура проекта

Данный документ описывает структуру AI-модуля ОРИКС и роль основных частей проекта.

## Общая идея архитектуры

Проект построен по гибридному принципу:

* Python выполняет точные расчёты;
* LLM формирует аналитический текст;
* валидатор проверяет корректность результата.

Это позволяет отделить математику от генерации текста.

## Основные части проекта

```text
src/
├── core/
│   ├── deterministic/
│   ├── nlg/
│   ├── pipeline.py
│   └── validator.py
├── models/
├── ui/
└── api.py
```

## 1. core/deterministic

В папке `core/deterministic` находятся калькуляторы метрик.

Каждый калькулятор отвечает за одну метрику.

Примеры:

```text
metric1_loss_share.py
metric3_loss_buckets.py
metric4_recovery.py
metric5_concentration.py
```

Калькуляторы выполняют:

* расчёт отклонений;
* сравнение с рынком;
* классификацию сценариев;
* подготовку данных для LLM.

## 2. core/nlg

Папка `core/nlg` отвечает за генерацию текста.

Здесь могут находиться:

* `prompt_builder.py`;
* `generator.py`;
* `llm_service.py`.

Эти файлы формируют промпт и отправляют его в LLM.

## 3. pipeline.py

`pipeline.py` управляет всем процессом обработки запроса.

Он соединяет:

* валидацию;
* выбор калькулятора;
* расчёт метрики;
* генерацию текста;
* проверку результата.

## 4. validator.py

`validator.py` проверяет корректность результата.

Он нужен, чтобы убедиться, что итоговый текст не противоречит расчётам.

## 5. models

Папка `models` содержит модели данных.

Обычно здесь находятся:

```text
input_models.py
output_models.py
enums.py
```

Эти файлы описывают структуру входных и выходных данных.

## 6. ui

Папка `ui` отвечает за веб-интерфейс проекта.

Если используется Streamlit, основной файл интерфейса может называться:

```text
app.py
```

Через интерфейс пользователь выбирает метрику, вводит данные и получает результат.

## 7. api.py

`api.py` может использоваться для запуска проекта через API.

Этот файл нужен, если проект работает не только через веб-интерфейс, но и как backend-сервис.

## Главный принцип

В проекте важно, что LLM не выполняет расчёты.

Расчёты выполняются только в Python-калькуляторах.

LLM получает:

* готовые числа;
* сценарий;
* дополнительные признаки;
* ограничения по стилю.

После этого LLM только оформляет аналитический вывод.

## Итоговая схема

```text
UI / API
↓
Input models
↓
Pipeline
↓
Validator
↓
Metric calculator
↓
MetricCalculations
↓
PromptBuilder
↓
LLM
↓
Output validator
↓
Final result
```
